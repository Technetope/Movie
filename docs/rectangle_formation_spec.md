# 矩形フォーメーション仕様書

## 1. 基本情報

### 1.1 ロボット数とフォーメーション
- **ロボット数**: 20台（ID: 0-19）
- **フォーメーション**: 固定相対位置（5列 × 4行）
- **動作**: 群全体が剛体として回転・移動

### 1.2 ロボット物理サイズ
- **長辺**: 72mm（横向き90°でX軸方向）
- **短辺**: 33mm（縦向き0°でY軸方向）
- **対角線長**: √(72² + 33²) ≈ 79.2mm
- **グリッド間隔**: 100mm（対角線長79.2mm + 安全マージン20.8mm）
  - 追突防止とlocomotion安定性のため、余裕を持たせた設定

**算出根拠**:
- 長辺: 1260mm ÷ 17.5 ≈ 72mm
- 短辺: 1187mm ÷ 36 ≈ 33mm

## 2. 座標系定義

### 2.1 フィールド座標系（Position ID座標）
- **座標系**: 画像座標系（左上原点）
- **X軸**: 右方向が正（34 → 949）
- **Y軸**: 下方向が正（35 → 898）
- **単位**: ピクセル（px）
- **範囲**: X: [34.0, 949.0], Y: [35.0, 898.0]

### 2.2 物理座標系（mm）
- **座標変換**:
  - X方向: 1.377 mm/px
  - Y方向: 1.376 mm/px
- **フィールド物理サイズ**:
  - 幅: (949 - 34) × 1.377 ≈ 1260mm
  - 高さ: (898 - 35) × 1.376 ≈ 1187mm

### 2.3 角度定義
- **0°**: 上向き（Y軸負方向、-Y方向）
- **90°**: 右向き（X軸正方向、+X方向）
- **180°**: 下向き（Y軸正方向、+Y方向）
- **-90° (270°)**: 左向き（X軸負方向、-X方向）
- **正の方向**: 時計回り（CW）

### 2.4 ローカル座標系（フォーメーション）
- **原点**: 群の中心（0, 0）
- **X軸**: 右方向（列方向、5列）
- **Y軸**: 前方向（行方向、4行）
- **単位**: mm
- **ピッチ**: 90mm

## 3. 動作シーケンス

### 3.1 ウェイポイント（群の中心座標、mm単位）
- **TL (Top-Left)**: (315.7, 267.0)
- **TR (Top-Right)**: (1037.9, 267.0)
- **BR (Bottom-Right)**: (1037.9, 1016.8)
- **BL (Bottom-Left)**: (315.7, 1016.8)

**算出根拠**:
- フォーメーションサイズ: 400mm（幅）× 300mm（高さ）
- フィールド境界からの安全マージン: 50ピクセル（約69mm）
  - locomotion安定性のため、十分な余裕を確保
- フィールド境界（mm）: X: [46.8, 1306.8], Y: [48.2, 1235.6]

### 3.2 動作フェーズ
1. **INIT**: 左上（TL）で初期化、向き90°
2. **MOVE_RIGHT**: 右上（TR）へ移動、向き90°維持
3. **TURN_DOWN**: その場で回転、90° → 180°
4. **MOVE_DOWN**: 右下（BR）へ移動、向き180°維持
5. **TURN_LEFT**: その場で回転、180° → -90°
6. **MOVE_LEFT**: 左下（BL）へ移動、向き-90°維持
7. **TURN_UP**: その場で回転、-90° → 0°
8. **MOVE_UP**: 左上（TL）へ移動、向き0°維持

### 3.3 タイミング（デフォルト）
- **回転時間**: 1.0秒
- **移動時間**: 10.0秒（引数で変更可能）

## 4. 座標変換ルール

### 4.1 mm → ピクセル
```python
px = mm / 1.377  # X方向
py = mm / 1.376  # Y方向
```

### 4.2 ピクセル → mm
```python
mm_x = px * 1.377  # X方向
mm_y = py * 1.376  # Y方向
```

### 4.3 ローカル座標 → グローバル座標（回転あり）
1. ローカル座標（mm）を回転行列で回転
2. 群の中心座標（mm）に加算
3. mm → ピクセルに変換

**回転行列**（時計回り、画像座標系）:
```
x' = x * cos(θ) - y * sin(θ)
y' = x * sin(θ) + y * cos(θ)
```

ただし、ロボット角度0°は数学角度-90°に対応するため、変換が必要。

## 5. データ構造

### 5.1 JSONフレーム形式
```json
{
  "time": 0.0,
  "x": 52.14,
  "y": 53.20,
  "rotation": 90.0,
  "use_position": true,
  "use_rotation": true,
  "stop_distance": 20.0,
  "angle_tolerance": 5.0,
  "sound": null
}
```

### 5.2 必須フィールド
- `time`: 時刻（秒、float）
- `x`, `y`: 座標（ピクセル、float）
- `rotation`: 角度（度、float、0-360）
- `use_position`: 位置指令の有効/無効（bool）
- `use_rotation`: 回転指令の有効/無効（bool）

### 5.3 オプションフィールド
- `stop_distance`: 停止距離（mm、デフォルト20.0）
- `angle_tolerance`: 角度許容誤差（度、デフォルト5.0）
- `sound`: 効果音ID（string | null）

## 6. コーディングルール

### 6.1 基本原則
- **明確性優先**: コードは自己説明的で、コメントなしでも理解できること
- **直接的な実装**: 謎のラッパー関数や謎のヘルパー関数を作らない
- **単一責任**: 各関数は1つの明確な目的を持つ
- **型の明確化**: すべての型を明示的に定義

### 6.2 型定義
- `Point`: `Tuple[float, float]` - ピクセル座標
- `PointMM`: `Tuple[float, float]` - mm座標
- `Heading`: `float` - 角度（度）

### 6.3 関数設計の禁止事項
- **禁止**: 目的が不明確なラッパー関数
- **禁止**: 複数の責任を持つ関数
- **禁止**: 内部状態を隠蔽する関数
- **推奨**: 計算ロジックを直接書く
- **推奨**: 定数や計算式を直接使用

### 6.4 座標変換
- すべての座標変換は明示的な関数で行う
- mmとピクセルの混在を避ける
- 変換係数は定数として定義
- 変換関数は単純で、1つの変換のみを行う

### 6.5 角度処理
- 角度は常に[0, 360)の範囲に正規化
- ラジアンを使用する場合は明示的に変換
- 角度の計算には`math.radians()`/`math.degrees()`を使用
- 角度の計算式は直接書く（ラッパー関数を作らない）

### 6.6 境界チェック
- すべての座標はフィールド境界内にクリップ
- クリップ処理は座標変換後に行う
- クリップ処理は明示的に行う（暗黙的な変換を避ける）

### 6.7 エラーハンドリング
- 無効な入力値は早期に検出してエラーを発生
- エラーメッセージは明確で、修正方法を示す
- エラーチェックは必要最小限に

### 6.8 状態管理
- 状態は明示的に追跡する
- 前の状態を保持する場合は、変数名を明確にする（例: `prev_heading`, `prev_center_mm`）
- 状態の更新は明確な場所で行う

## 7. 検証項目

### 7.1 座標の妥当性
- すべての座標がフィールド境界内
- ロボット間の距離が90mm以上（回転時も）

### 7.2 角度の妥当性
- すべての角度が[0, 360)の範囲
- 連続するフレーム間の角度変化が妥当

### 7.3 時間の妥当性
- フレームの時刻が単調増加
- 時間間隔が妥当（速度制限内）
