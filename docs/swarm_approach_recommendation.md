# 50-120秒「群の動き」実装アプローチの推奨

## 最終ゴールの確認

**最終ゴール**: toioロボット用のJSONファイル出力
- 形式: `{ "sets": [{ "id": "robot_XX", "frames": [...] }] }`
- 各フレーム: `{ "time", "x", "y", "rotation", "use_position", "use_rotation", ... }`
- 50-120秒の全ロボットの軌跡をJSONとして生成

## 私の意見

### 1. Boidモデルを5%に下げることについて

**結論**: 5%に下げても根本的な問題は解決しない可能性が高い

**理由**:
- 15%でも「重なりまくりで変な動きしかしない」問題が発生している
- 5%に下げると、Boidモデルの効果がほぼなくなり、実質的に削除するのと同じ
- それなら最初からBoidモデルを完全に排除し、別のアプローチを採用すべき

**推奨**: Boidモデルは**完全に排除**し、以下のアプローチを採用

---

### 2. オフライン軌跡生成アプローチの推奨

**重要な認識**: 最終ゴールがJSONファイルの出力であるため、**リアルタイムシミュレーションは不要**

**現在の問題**:
- `swarm_control_p5js`はリアルタイムシミュレーション（60fps）を前提としている
- しかし、最終的にはJSONファイル（離散的なフレーム列）を出力すればよい
- リアルタイム性を追求する必要はない

**推奨アプローチ**: **オフライン軌跡生成**

1. **時間を離散的にサンプリング**（例: 0.5秒間隔）
2. **各時刻での位置・姿勢を計算**（衝突回避を含む）
3. **JSONフレームとして出力**

**利点**:
- 計算時間を気にせず、正確な衝突回避が可能
- 後から調整・最適化が容易
- 検証が容易（全時刻の軌跡を事前に確認できる）

---

### 3. swarm_control_p5jsから抽出すべき有効な工夫

Boidモデルを排除しつつ、以下の工夫は有効：

#### 3.1 多層的な衝突回避（Boidモデルなし）
- ✅ **緊急停止モード**: 71mm以下で15%に減速 + 強力な反発力
- ✅ **予測的衝突回避**: 0.5秒、1秒、2秒先を予測
- ✅ **混雑度推定**: 空間グリッドで混雑度を計算し、低い方向に移動
- ❌ **Boidモデル**: 完全に削除

#### 3.2 個体差の導入
- ✅ **速度分布**: 20%速い、60%中程度、20%遅い
- ✅ **個体パラメータの変動**: 各ロボットで異なるパラメータ
- **効果**: 群全体が同時に同じ動きをしない

#### 3.3 自律性システム（Boidモデルなし）
- ✅ **相関ランダムウォーク**: 前の方向から小さな角度変化
- ✅ **恒常性システム**: エネルギーが減衰し、探索を促進
- ✅ **局所最小値からの脱出**: 2秒間動かない場合、強制的に方向変更
- ❌ **Boidモデル**: 完全に削除

#### 3.4 人間との相互作用
- ✅ **ポテンシャル場による回避**: 人間領域を負のポテンシャルとして定義
- ✅ **人間の足の間を通り抜ける**: 立っている場合、20%のロボットが50cm以内で5台に限定

### 4. 推奨される実装アプローチ

#### 4.1 基本方針
1. **Boidモデルを完全に排除**
2. **オフライン軌跡生成**（リアルタイムシミュレーションではない）
3. **多層的な衝突回避**（緊急停止、予測回避、混雑度回避）
4. **個体差の導入**（速度分布、個体パラメータ）
5. **自律性システム**（相関ランダムウォーク、恒常性）

#### 4.2 実装の流れ

```python
# 疑似コード
def generate_swarm_trajectories(initial_state, human_zones, duration=40.0):
    """
    50-120秒の群の動きを生成
    
    Args:
        initial_state: 50秒時点の初期状態
        human_zones: 人領域の定義（時刻付き）
        duration: 生成する時間（秒）
    
    Returns:
        Dict[int, List[Frame]]: ロボットID → フレームリスト
    """
    dt = 0.5  # 0.5秒間隔でサンプリング
    robots = initialize_robots(initial_state)
    
    frames = {rid: [] for rid in range(20)}
    
    for t in range(50.0, 120.0, dt):
        # 1. 人間領域のポテンシャル場を計算
        potential_field = compute_potential_field(human_zones, t)
        
        # 2. 各ロボットの自律性を更新（Boidモデルなし）
        for robot in robots:
            robot.update_autonomy(dt, potential_field, robots)
        
        # 3. 多層的な衝突回避を適用
        for robot in robots:
            robot.apply_collision_avoidance(robots, dt)
            robot.apply_predictive_avoidance(robots, dt)
            robot.apply_density_avoidance(density_grid, dt)
        
        # 4. 位置を更新
        for robot in robots:
            robot.update_position(dt)
        
        # 5. JSONフレームを生成
        for robot in robots:
            frames[robot.id].append(make_frame(t, robot))
    
    return frames
```

#### 4.3 衝突回避の優先順位

1. **緊急停止**（71mm以下）: 最優先、速度を15%に減速
2. **予測的衝突回避**（0.5秒先）: 次に優先
3. **混雑度回避**: 局所的な混雑を分散
4. **通常の反発力**: 80mm以上の場合

**Boidモデルは一切使用しない**

### 7. まとめ

**結論**:
1. **Boidモデルは完全に排除**（5%に下げるのではなく、0%にする）
2. **オフライン軌跡生成**を採用（リアルタイムシミュレーションではない）
3. **多層的な衝突回避**を実装（緊急停止、予測回避、混雑度回避）
4. **個体差と自律性**を強化（Boidモデルに頼らない）

**理由**:
- 最終ゴールがJSONファイルの出力であるため、リアルタイム性は不要
- Boidモデルは根本的に重なりを引き起こすため、確率を下げても解決しない
- オフライン生成により、正確な衝突回避と検証が可能
